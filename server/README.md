# Planner Server 0.1.1

Серверная поставка для Windows 11, Docker Desktop и WSL2. Она содержит HTTP API, PostgreSQL, фоновую обработку почты, файловое хранилище и средства резервного копирования. Клиент macOS пока использует локальную библиотеку: подключение его интерфейса к этому API выполняется следующим этапом.

**Для уже установленной 0.1.0:** следуйте [инструкции обновления Windows](docs/UPGRADE-WINDOWS.ru.md). Новый архив сначала распаковывается в отдельный каталог; обновление запускается оттуда.

## Что входит

- Вход по почте и паролю, подтверждение почты, сброс пароля, устройства и отзыв сессий.
- Отдельная библиотека для каждого аккаунта, операции задач/папок/подзадач, версии отдельных полей, журнал изменений и первоначальный импорт.
- Приватные вложения до 100 МиБ, загрузка частями 8 МиБ, продолжение после обрыва, SHA-256 и квота 1 ГиБ на аккаунт.
- Dockerfile и Compose с закрытым PostgreSQL и HTTP-портом только на `127.0.0.1:3030`.
- PowerShell-скрипты установки, отдельной сборки, запуска, обновления и возврата версии, диагностики, копирования, восстановления и заданий планировщика.
- [Контракт API](docs/API.md), [OpenAPI](docs/openapi.json), [результаты проверки](docs/VERIFICATION.md).

## Установка на другом компьютере Windows

Распакуйте ZIP во временный каталог. Скопируйте **содержимое `app`** из архива в уже подготовленную папку `C:\PlannerServer\app`. Папки `C:\PlannerServer\config`, `logs` и `backup-staging` сохраняются. В поставке отсутствуют личные настройки и пароли.

Далее работайте в PowerShell на **Windows-компьютере**:

```powershell
Set-Location C:\PlannerServer\app
Get-FileHash "C:\путь-к-архиву\PlannerServer-0.1.1-Windows.zip" -Algorithm SHA256
```

Сверьте контрольную сумму ZIP по отдельному `.sha256`. Скрипты также автоматически проверяют файлы поставки по `SHA256SUMS.json` перед запуском. Серверные данные будут храниться в собственных томах Compose-проекта `planner-server`, внутри Docker Desktop на Windows. Приложения и контейнеры других проектов не используются.

Создайте конфигурацию. Вместо примеров укажите свои адреса:

```powershell
.\scripts\Initialize-Server.ps1 -SenderEmail "your-service@yandex.ru" -AllowedEmails "your-personal@example.com"
```

Скрипт запросит SMTP-пароль приложения скрытым вводом, создаст случайные секреты и `C:\PlannerServer\config\server.env`. Существующий файл он не перезаписывает. Доступ к `config` и временному каталогу копий ограничивается владельцем, SYSTEM и администраторами Windows. Адреса в `AllowedEmails` разделяются запятыми; публичная регистрация по умолчанию закрыта.

Сохраните `RESTIC_PASSWORD` из локального файла конфигурации в своём менеджере паролей отдельно от резервного репозитория. Без него зашифрованные копии восстановить нельзя. Файл конфигурации и пароль SMTP остаются на сервере.

Если Windows блокирует запуск скачанных скриптов, после проверки архива разблокируйте только файлы этой поставки:

```powershell
Get-ChildItem .\scripts\*.ps1 | Unblock-File
```

Для системной политики, всё ещё блокирующей запуск, используйте `powershell.exe -NoProfile -ExecutionPolicy Bypass -File` с конкретным скриптом, не меняя общую политику Windows.

Запустите поставку:

```powershell
.\scripts\Build-Server.ps1
.\scripts\Start-Server.ps1
.\scripts\Get-ServerStatus.ps1
.\scripts\Test-Mail.ps1 -To "your-personal@example.com"
```

Первая сборка через `Build-Server` требует доступа к Docker Hub и npm; скрипт также загружает PostgreSQL и restic. `Start-Server` ждёт готовности Docker, проверяет Compose, применяет миграции и запускает API с worker из локальных образов с `--no-build --pull never`. При отсутствии образа он просит сначала выполнить сборку. Успех подтверждается ответом `ready` от `http://127.0.0.1:3030/health/ready`. Проверка почты отправляет реальное тестовое письмо на адрес из `-To`.

## HTTPS после локальной проверки

До настройки настоящего адреса в конфигурации используется явно обозначенный `https://replace-before-publication.invalid`. Он позволяет проверить локальный сервер, но не является адресом подключения клиентов.

На Windows, где работает сервер, настройте установленный Tailscale:

```powershell
tailscale funnel --bg http://127.0.0.1:3030
tailscale funnel status
```

Полученный реальный HTTPS origin запишите в `PUBLIC_BASE_URL` в локальном `config\server.env` и повторите `Start-Server.ps1`. Остальные секреты сохраняются. Из внешней сети проверьте `/health/ready`, затем передайте только публичный URL для конфигурации будущей клиентской сборки.

Funnel публикует только API. Порты базы, Docker API, файловые папки и почтовые настройки наружу не открываются. Автоматический запуск Docker зависит от входа владельца в Windows; при выключенном компьютере сервер недоступен. [Полная подготовка Windows](../docs/windows-server-setup.ru.md).

## Управление

```powershell
.\scripts\Get-ServerStatus.ps1
.\scripts\Stop-Server.ps1
.\scripts\Start-Server.ps1
```

Остановка сохраняет тома. Не используйте `docker compose down -v` для рабочего проекта: эта команда удаляет его данные. Удаление контейнера или образа также не является заменой резервной копии.

## Зашифрованная резервная копия

Укажите `BACKUP_REPOSITORY_PATH` в `config\server.env`, например `E:/PlannerBackups` на отдельном носителе. Значение — путь Windows с прямыми слешами. Если нужен другой носитель, укажите его фактический путь. Каталог первого репозитория должен быть пустым.

```powershell
.\scripts\Backup-Server.ps1 -FullCheck
```

Скрипт кратковременно включает обслуживание, делает `pg_dump`, копирует проверенные файлы и создаёт манифест. После этого запись в API возобновляется, а подготовленный комплект сохраняется restic с шифрованием. С `-FullCheck` читается весь репозиторий для проверки данных; без параметра выполняется структурная проверка. Проверяются свободное место и отдельный том репозитория, предотвращается параллельное обслуживание. Применяются правила хранения 7 ежедневных и 4 еженедельных снимков в пределах 30 дней, временные незашифрованные файлы удаляются. Файл конфигурации с секретами в комплект не входит — его нужно хранить отдельно.

При аварийном завершении процесса обслуживания может потребоваться снять флаг вручную из этой поставки:

```powershell
docker compose --project-name planner-server --env-file ..\config\server.env exec -T api node dist/main.js maintenance off
```

## Проверка восстановления

Скопируйте ID снимка из результата резервного копирования:

```powershell
.\scripts\Restore-Server.ps1 -Snapshot "SNAPSHOT_ID"
```

По умолчанию создаётся новый проект `planner-restore-<время>` с собственными пустыми томами и портом `13030`. Скрипт отказывается использовать рабочий проект или существующие тома назначения, проверяет манифест и SHA-256, восстанавливает базу и файлы, отзывает прежние сессии и удаляет отложенные письма. Worker не запускается; Tailscale на тестовое восстановление не переключается.

Проверьте восстановленные задачи через API и сравните файлы. Рабочие тома сохраняются. Перенос восстановленного экземпляра в рабочую роль выполняется отдельным явным действием после проверки; автоматического переключения нет.

## Диагностика и планировщик Windows

`Get-ServerStatus.ps1 -Json` выдаёт операторские сведения о worker, очереди почты, безопасных кодах SMTP, свободном месте данных и результатах резервного копирования. Публичных административных методов нет. `/health/ready` подтверждает API, базу и файловый каталог; доставка почты проверяется отдельно.

Для настройки `TRUSTED_PROXY_CIDRS` используйте `Test-Proxy.ps1` и `Test-Proxy.ps1 -Results`. Доверие по умолчанию выключено; разрешаются только явные IP/CIDR контролируемого прокси. Подробная проверка двух внешних сетей и подмены заголовков описана в [инструкции обновления](docs/UPGRADE-WINDOWS.ru.md).

После проверки копирования и восстановления `Install-ServerTasks.ps1 -BackupTime "03:00"` создаёт запуск при входе текущего владельца и ежедневную копию с полной проверкой. Docker Desktop должен запускаться при входе. Питание и Resource Saver настраиваются отдельно. Удаление этих заданий — `Remove-ServerTasks.ps1`.

## Разработка и тесты

Изолированные тесты требуют Node.js 24 и отдельную PostgreSQL. Имя тестовой базы обязательно начинается с `planner_delivery_test`; тесты очищают только её.

```sh
npm ci
npm run build
TEST_DATABASE_URL=postgres://USER:PASSWORD@127.0.0.1:PORT/planner_delivery_test npm test
node scripts/export-contract.mjs
# Optional PowerShell orchestration test with fake Docker and isolated files:
pwsh -NoProfile -File test/windows-scripts.test.ps1
```

Схемы и SQL-миграции добавляются новыми файлами. При изменении wire-формата обновляются версия протокола, OpenAPI, примеры и тесты совместимости. Не включайте в архив `node_modules`, `.env`, базы, резервные копии или журналы с личными данными.

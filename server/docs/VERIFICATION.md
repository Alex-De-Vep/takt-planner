# Проверка серверной поставки 0.1.1

Дата: 6 ноября 2026 года. Рабочая установка предназначена для отдельного компьютера Windows 11 с Docker Desktop/WSL2. Проверки ниже выполнены на временных данных на Mac; действующий Windows-сервер не изменялся.

## Автоматические проверки

- TypeScript компилируется. Зависимости закреплены lock-файлом; `npm audit` при подготовке сообщил 0 известных уязвимостей. Неиспользуемый `@fastify/rate-limit` удалён: ограничения теперь хранятся в PostgreSQL.
- **37 из 37 интеграционных тестов** на отдельной PostgreSQL 18: все прежние 26 плюс схемы OpenAPI и фактических ответов, сохранение полей при сериализации, недопустимые настройки прокси, разделение внешних IP, защита от поддельных заголовков недоверенного отправителя, независимые лимиты пользователей и refresh-сессий, фактический `Retry-After`, безопасная диагностика SMTP, heartbeat worker, временная локальная диагностика прокси и отказ от симлинков за пределы каталога копии.
- Синтаксис **14 PowerShell-скриптов** проверен штатным парсером PowerShell 7.4. Дополнительный тест выполняет настоящий код скриптов на изолированных файлах с подменой Docker: успешное обновление, сохранение конфигурации и маркера данных, возврат при отказе нового запуска, ручной возврат, запуск без сборки/скачивания, отказ при отсутствии образа, блокировка одновременных операций внутри процесса и проверка свободного места. Этот тест проверяет оркестрацию, а не выполнение Docker на Windows.
- Собран образ **linux/amd64**, соответствующий целевому Windows-компьютеру. В настоящем Compose созданы вымышленные аккаунт, библиотека, задача и вложение версии 0.1.0. Подтверждение почты прошло через worker и отдельный SMTP Mailpit.
- Выполнен реальный переход образов **0.1.0 → 0.1.1 → 0.1.0 → 0.1.1** с одним хранилищем. Существующая сессия, UUID библиотеки, задача и байты вложения сохранились. Запуск использовал `--no-build --pull never`.
- Пройден полный цикл 0.1.1: обслуживание → `pg_dump` → файлы и манифест SHA-256 → шифрованный restic → `check --read-data` → новый пустой restore-проект → `pg_restore` и восстановление файлов → вход, исходная задача и побайтовое совпадение вложения. Старые сессии отзываются при восстановлении; worker восстановленного проекта не запускается.
- Упаковщик проверяет ZIP, SHA-256 каждого файла и отсутствие локальных настроек, персональных данных, резервных копий и `node_modules`. Манифест `SHA256SUMS.json` проверяется PowerShell-скриптами; отдельно поставляется сумма ZIP.

## Особенности среды проверки

На этом Mac Docker Desktop/restic ранее возвращал `input/output error` при чтении источника из общей папки хоста. В полном тестовом прогоне подготовленный комплект копировался в Linux tmpfs, откуда restic читал его для шифрования. Проверка всего репозитория и отдельное восстановление прошли. Производственные Windows-скрипты используют `backup-staging` напрямую; это поведение обязательно проверить на целевой машине, не заменяя его результатом Mac-прогона.

PowerShell работал в Linux-контейнере, часть Docker-команд в тестах оркестрации была подменена. На целевой Windows дополнительно проверяются Windows PowerShell 5.1/PowerShell 7, NTFS ACL и межпроцессная блокировка FileShare.None, Task Scheduler и фактическое выполнение скрипта обновления. Разбор синтаксиса и тесты с подменой Docker не выдаются за такую проверку.

## Приёмка на Windows после переноса

1. Проверенная копия 0.1.0 на отдельный носитель и восстановление в отдельный проект до обновления.
2. Обновление по `UPGRADE-WINDOWS.ru.md`, версия 0.1.1, прежние аккаунты, задачи и файлы, неизменные конфигурация и публичный адрес.
3. Фактическая цепочка Tailscale → Windows → Docker: доверенный адрес прокси, два внешних подключения и перезапись подставленного X-Forwarded-For. Синтетические запросы интеграционных тестов не доказывают конфигурацию конкретного Windows-хоста.
4. Полная регистрация/подтверждение/вход/refresh/сброс пароля с настоящим Яндекс SMTP. Mailpit не доказывает доставку через Яндекс.
5. Копия 0.1.1, `-FullCheck`, отдельное восстановление и сравнение данных; отказы при недоступном носителе, нехватке места и параллельной операции.
6. Задания текущего владельца, журнал копии, перезагрузка Windows, вход, старт Docker, блокировка экрана, питание и внешний health.

Схема SQL и протокол 1 сохранены. Поставка содержит серверную часть; подключение приложения macOS ещё предстоит. Публичный API при подготовке 0.1.1 не обновлялся, реальные аккаунты и письма не создавались.

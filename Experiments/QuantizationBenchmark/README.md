# Сравнение Qwen3.5-4B: 4-bit и 3-bit

Эксперимент запускается отдельно от пользовательской библиотеки. Рабочий `Planner/Assistant/ModelManifest.json`, настройки, код приложения и установочные образы сохраняются без изменений.

## Модели

- Рабочая 4-bit: `mlx-community/Qwen3.5-4B-4bit`, ревизия `0e7ffd5c629ef7719d4cbc04069232580bfa9d9c`; тестовые файлы `.build/ModelCache4`.
- Экспериментальная 3-bit: `mlx-community/Qwen3.5-4B-3bit`, ревизия `6a87bc4e52f513d6d68397b844db31a255f3fb19`; `.build/QuantizationBenchmark/Models/3bit`.
- Архитектура/текстовая конфигурация совпадают. В конфигурации отличаются только `quantization` и `quantization_config`. Текстовые веса: 2 367 118 848 и 1 841 520 128 байт. Визуальная часть по 667 028 480 байт не используется текстовым загрузчиком.

Скачивание: около 2,54 GB для 3-bit; сохраняются закреплённая ревизия и SHA-256 каждого файла. Большие файлы сверяются с LFS SHA-256, небольшие — с Git blob ID закреплённой ревизии.

## Методика

Порядок ABBA: **4-bit → 3-bit → 3-bit → 4-bit**, каждый прогон в новом тестовом процессе, по 18 запросов. Модели не загружаются одновременно. Используется существующий `MLXAssistantBackend` приложения: MLX Swift LM 2.31.3, temperature=0, maxTokens=1800, prefill=512, thinking=false, свободный кеш 128 MiB. Повтор невалидного формата выполняется по правилам приложения и включён во время ответа. Дополнительных попыток ради результата нет.

Первый прогон сохраняет точные тексты промптов и снимки контекста; остальные читают те же байты. Системная инструкция идентична во всех прогонах. Контекст уточнения и исправления предложений задан заранее, чтобы различия предыдущих ответов не меняли последующие входные данные.

Измерения:

- активная память MLX после загрузки и её пик во время обработки;
- физический footprint всего тестового процесса, включая Metal, с опросом каждые 20 мс;
- время подготовки/повторной подготовки локальных весов;
- полное время ответа до выдачи JSON, включая предусмотренный приложением повтор формата;
- освобождение памяти после выгрузки.

Время полного ответа зависит от длины и содержания результата. Это оценка пользовательской задержки, не измерение чистых токенов в секунду. Кеш файлов ОС и фоновые приложения не фиксируются; ABBA уменьшает влияние порядка, но два прогона не дают статистической гарантии. Память измеряется у Debug/SHOWCASE-процесса вместе с раннером тестов, не у Release.

Качество проверяется по папке, сроку, звезде, количеству и смыслу подзадач, дате/времени/длительности/календарю/напоминанию события, уточнениям и связям с задачами. Проверяются неизвестная папка, текущая папка по умолчанию, английский запрос, длинная переписка и исправление карточки. Полностью пройденный сценарий должен выполнить все его условия. Валидный JSON сам по себе не означает правильное выполнение запроса.

После разбора вызывается реальный путь применения предложений с **SwiftData in-memory и FakeCalendarStore**. Никаких личных календарей или сохранений в рабочую библиотеку. Ошибка модели записывается в результат и не прерывает сбор остальных примеров; успешный статус самого тестового раннера означает завершение эксперимента, а не правильность всех ответов модели.

## Воспроизведение

Из корня репозитория, Xcode/Metal Toolchain уже установлены:

```sh
python3 Experiments/QuantizationBenchmark/download_model.py
python3 Experiments/QuantizationBenchmark/run.py
python3 Experiments/QuantizationBenchmark/summarize.py
```

Тест `AssistantQuantizationBenchmark` выключен без специальной переменной окружения. Скрипт временно создаёт две схемы Xcode, затем убирает их. Для инкрементальной сборки используется `.build/AIModel4DerivedData`; подписанный установочный образ не пересобирается.

Тестовые результаты сначала записываются в отдельный временный каталог песочницы тестового приложения, затем копируются в `.build/QuantizationBenchmark/Outputs`. Это сохраняет песочницу: расширение доступа к файловой системе для тестового приложения не требуется.

Скрипт проверяет контрольные суммы рабочей тестовой 4-битной модели и исходников приложения. Промежуточные журналы, файлы моделей и полные результаты находятся в `.build/QuantizationBenchmark`, за пределами Git. Здесь публикуются только методика и итоговый отчёт по вымышленным запросам.

Инструкция к [плану хранения и синхронизации](storage-sync-plan.ru.md), 3 ноября 2026 года. Целевой компьютер — Windows 11 с 16 ГБ памяти. Сервер работает в Linux-контейнерах Docker Desktop с WSL2. Основное приложение macOS продолжает работать отдельно.

## Обновление сведений на 6 ноября 2026 года

По отчёту владельца сервер 0.1.0 уже установлен в `C:\PlannerServer`, API работает, SMTP проверен, публичный HTTPS включён: `https://planner-server.tail037e91.ts.net`. Резервный носитель, восстановление на Windows и эксплуатационные проверки остаются незавершёнными. Ниже сохранены шаги подготовки; уже выполненные пункты повторять не требуется.

Подготовлена поставка 0.1.1 с [отдельной инструкцией обновления](../server/docs/UPGRADE-WINDOWS.ru.md). В ZIP эта инструкция лежит в `app/docs/UPGRADE-WINDOWS.ru.md`; сначала выполните описанные в ней предварительные проверки. Установка 0.1.1 на действующей Windows этим документом не подтверждается.

## Что подготовить

| Что | Назначение |
|---|---|
| Windows 11 с обновлениями и включённой виртуализацией | Запуск WSL2 и Docker Desktop |
| WSL2 и Docker Desktop | Работа API, базы и фоновых заданий |

## Шаг 1 Проверить Windows и существующие установки

Открыть обычный PowerShell и выполнить по отдельности:

```powershell
Get-CimInstance Win32_OperatingSystem | Select-Object Caption, Version, OSArchitecture
Get-CimInstance Win32_Processor | Select-Object Name, VirtualizationFirmwareEnabled
wsl --version
wsl --status
wsl --list --verbose
docker version
docker compose version
```

Если команда не найдена, соответствующий компонент ещё не установлен. У `docker version` важны и Client, и Server: наличие только клиента не подтверждает работающий Docker Engine.

В диспетчере задач открыть «Производительность → ЦП» и проверить строку «Виртуализация». Если она выключена, включить аппаратную виртуализацию в BIOS/UEFI по инструкции производителя компьютера.

По документации Docker нужны поддерживаемая версия Windows и WSL не ниже 2.1.5; окончательную совместимость проверять по фактической сборке Windows. [Требования Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/).

## Шаг 2 Установить или обновить WSL2

Если WSL ещё не установлен, открыть PowerShell от администратора:

```powershell
wsl --install
```

Перезагрузить компьютер и закончить первичную настройку установленного Linux-дистрибутива. Учётные данные Linux сохраняются у владельца компьютера.

Если WSL уже установлен:

```powershell
wsl --update
wsl --set-default-version 2
wsl --list --verbose
```

`--set-default-version 2` задаёт версию для новых установок. Если существующий нужный дистрибутив показывает версию 1, преобразование выполняется отдельно по его фактическому имени после резервного копирования важных файлов. [Инструкция Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install).

## Шаг 3 Настроить Docker Desktop

Установить Docker Desktop с [официальной страницы](https://docs.docker.com/desktop/setup/install/windows-install/), выбрать WSL2 и Linux containers. Запустить приложение.

В настройках:

1. Включить использование WSL2 Engine.
2. Включить запуск Docker Desktop при входе в Windows.
3. Отключить Resource Saver для постоянно обслуживающего запросы сервера.
4. Для первого запуска оставить штатные лимиты WSL/Docker. При недостатке доступной памяти Windows отдельно настроить предел WSL; настройка лимита Hyper-V к WSL2 не применяется.
5. Место хранения данных Docker выбрать на SSD с достаточным свободным местом; начальный запас для пилота — 20 ГБ, затем учитывать реальный объём вложений и копий.

Проверка:

```powershell
docker version
docker compose version
docker run --rm hello-world
```

Последняя команда скачивает и запускает официальный тестовый образ. Готовность: есть ответ Docker Server и сообщение успешного тестового контейнера.

Docker Desktop запускается после входа пользователя, а не гарантированно до него. После перезагрузки сначала нужно войти в Windows; после запуска Docker экран можно заблокировать. [Настройки Docker](https://docs.docker.com/desktop/settings-and-maintenance/settings/).

## Шаг 4 Подготовить отправку писем

Создать отдельный ящик Яндекс Почты для приложения. Включить защиту аккаунта и сохранить способ восстановления доступа.

В настройках Яндекс Почты разрешить использование почтовых клиентов и паролей приложений. В Яндекс ID создать отдельный пароль приложения типа «Почта» с названием `Planner server`. [Инструкция паролей приложений](https://yandex.ru/support/id/ru/authorization/app-passwords), [настройки почтовых клиентов](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others.html).

Значения для будущей конфигурации сервера:

```dotenv
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=<полный адрес технического ящика>
SMTP_PASSWORD=<пароль приложения для почты>
MAIL_FROM=<тот же полный адрес ящика>
```

Это шаблон, а не готовая конфигурация. Ввести реальные секреты локально в закрытый конфигурационный файл Windows-сервера. Для проверки в чате достаточно адреса отправителя и результата отправки; пароль и содержимое файла конфигурации остаются на сервере.

После реализации серверной части `Test-Mail.ps1` отправит тестовое письмо на указанный владельцем адрес. Проверить получение, папку спама и правильного отправителя. Отдельно проверить письма регистрации и восстановления — успешного SMTP-соединения недостаточно.

Если позднее подключать Selectel, зарегистрировать собственный домен и выполнить его подтверждение и настройку DNS. Selectel здесь выступает SMTP-сервисом отправки; базу и вложения переносить к нему не требуется. [Подключение Selectel SMTP](https://docs.selectel.ru/email-service/connect-email-service/).

## Шаг 5 Подготовить Tailscale для HTTPS

Установить [Tailscale для Windows](https://tailscale.com/download/windows) и войти в свою учётную запись. Задать серверу устойчивое имя, например `planner-server`. Это предлагаемое имя устройства, а не уже созданный адрес.

В учётной записи Tailscale разрешить необходимые для Funnel MagicDNS, HTTPS и публикацию Funnel для серверного устройства. Tailscale оформляет TLS-сертификат и выдаёт адрес вида `https://planner-server.<имя-сети>.ts.net`.

Адрес сохраняется при сохранении аккаунта и имён сети/устройства. После подключения клиентов имя сервера не менять. Funnel имеет статус beta и ограничения пропускной способности; он подходит для первого домашнего пилота, круглосуточная доступность отдельно не гарантируется. [Устройство Funnel](https://tailscale.com/docs/features/tailscale-funnel).

Публикацию порта включать после появления защищённого API. Не направлять Funnel на файловую папку Windows, PostgreSQL или Docker API.

## Шаг 6 Перенести и запустить серверную поставку

Подготовлена серверная поставка 0.1.0: Compose, API, миграции, файловое хранилище и PowerShell-скрипты. Она устанавливается на отдельном Windows-компьютере, а не на Mac с проектом. Полная инструкция находится в `app/README.md` внутри архива; результаты тестов — в `app/docs/VERIFICATION.md`. Клиент macOS пока работает локально, его подключение к серверу — следующий этап.

1. Проверить контрольную сумму ZIP, распаковать и скопировать содержимое `app` в `C:\PlannerServer\app`, вне OneDrive и других синхронизируемых каталогов. Существующие соседние `config`, `logs`, `backup-staging` сохранить.
2. В PowerShell перейти в `C:\PlannerServer\app`. Выполнить `scripts\Initialize-Server.ps1` с адресами `-SenderEmail` и `-AllowedEmails`: скрыто ввести SMTP-пароль приложения. Скрипт создаёт секреты в соседнем `config\server.env`, существующий файл не перезаписывает.
3. Запустить поставляемый `Start-Server.ps1`, который проверяет конфигурацию, Docker, запускает миграции и Compose. Подготовить постоянные volume для PostgreSQL, файлов и незавершённых передач.
4. Проверить `http://127.0.0.1:3030/health/ready` на Windows. Ожидается готовность API, базы и каталога хранения. Публичное содержимое healthcheck не раскрывает секреты и данные пользователей.
5. Только после успешной проверки включить Funnel из PowerShell:

```powershell
tailscale funnel --bg http://127.0.0.1:3030
tailscale funnel status
```

Если `tailscale` не найден, перезапустить PowerShell после установки или вызвать установленный CLI по его фактическому пути. Скопировать именно тот HTTPS-адрес, который покажет команда.

Флаг `--bg` сохраняет публикацию при перезапуске Tailscale и компьютера; само API по-прежнему зависит от работающего Docker. [Команда Funnel](https://tailscale.com/docs/reference/tailscale-cli/funnel).

6. Записать полученный HTTPS origin в `PUBLIC_BASE_URL` файла `config\server.env` и повторить `Start-Server.ps1`. С Mac через другую сеть или с телефона через мобильный интернет открыть полученный адрес с путём `/health/ready`. Проверить TLS и отсутствие необходимости в клиентском VPN.
7. Передать публичный HTTPS-адрес для конфигурации macOS-сборки. После реализации клиентского подключения проверить регистрацию, вход и обмен вымышленными задачами из приложения.

## Шаг 7 Автозапуск и питание

- Настроить запуск Docker Desktop при входе владельца в Windows.
- Поставляемый `Start-Server.ps1` добавить в планировщик на вход владельца: он ожидает готовности Docker и идемпотентно запускает Compose. Публикация Funnel уже сохраняется через `--bg`.
- На время работы сервера отключить автоматический сон компьютера при питании от сети; экран может выключаться. Крышка ноутбука не должна уводить сервер в сон. Настройки питания меняет владелец компьютера.
- После перезагрузки войти в Windows, дождаться Docker и проверить `/health/ready` извне. Отдельно проверить блокировку экрана и пробуждение.
- Автоматический вход в Windows с сохранением пароля не нужен. Полностью автоматическое восстановление до входа пользователя не входит в вариант с Docker Desktop.

При выключении сервера приложения показывают ожидание соединения и сохраняют изменения локально. После включения обмен возобновляется. Настройка автообновлений Windows должна предусматривать время перезагрузки и последующий вход владельца.

## Шаг 8 Подготовить резервное копирование

Выбрать отдельный носитель или второй компьютер для зашифрованных резервных копий. Сохранить ключ восстановления отдельно. Копия на том же SSD не защищает от отказа SSD или потери компьютера.

Использовать поставляемый `Backup-Server.ps1` для согласованной копии базы и файлов. Поставляемая процедура восстановления проверяется на отдельном тестовом Compose-проекте, не поверх рабочей библиотеки. В резервную копию входят манифест, версия сервера и контрольные суммы файлов.

Ежедневное задание, проверку свободного места и тест восстановления настроить до начала хранения важных данных. В журнале резервного копирования достаточно статуса, времени и размера — содержимое задач туда не выводится.

## Что сообщить после подготовки

- Версию и сборку Windows, результат проверки виртуализации.
- Результаты `wsl --version`, `wsl --list --verbose`, `docker version` и `docker compose version`.
- Адрес созданного технического ящика и готовность SMTP-пароля, без самого пароля.
- Готовность Tailscale и имя серверного устройства; HTTPS-адрес — после публикации готового API.
- Где будут храниться резервные копии и сможет ли компьютер оставаться включённым.

Подготовку можно выполнять по шагам. Сначала достаточно закончить проверку Windows, WSL2 и Docker и сообщить результаты; сетевую публикацию и проверку почты выполняем после появления серверной поставки.

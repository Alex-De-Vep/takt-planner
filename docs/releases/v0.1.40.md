# Tasks 0.1.40

Build 41 includes the other changes from [0.1.39](v0.1.39.md) and updates list animation after reports of abrupt insertions and removals in that version.

## Task list animation

- The SwiftData query supplies the 0.26-second animation transaction when saved changes update the results.
- Creating a task skips forced scrolling if its row is already visible. If the list is scrolled down, it still animates to the new task.
- Automatically selecting a neighbor after deletion keeps the current scroll position in both active and completed tasks.
- Reduce Motion disables the animation transaction, including animation from the query.

## Folder highlights and drag and drop

- Each row uses the native `backgroundProminence` to determine its title and icon colors. Color changes are immediate. The open folder is purple with white contents when focused and gray with purple contents when unfocused. Unselected rows use the system primary color.
- Starting a drag moves keyboard focus to the source list and keeps the current task selection. The open folder turns gray before the pointer reaches another folder.
- A drop destination uses a separate purple highlight with white contents. Hovering leaves the open folder, editor, and task list in place. A task’s current folder stays gray and accepts a drop without moving the task, including from Today and All Tasks.
- The temporary drag context tracks only the gesture and task identifiers and the task’s primary folder. It stays out of SwiftData. The highlight clears on pointer exit or drag end. The context clears on completion, cancellation, or release outside the app. A delayed callback from an earlier drag leaves the current drag intact.
- Row sizing, insets, and insertion and deletion animations are preserved. Keyboard focus stays in the source list after the drag.

## Verification

Regression sources cover drag context, dropping into the current folder, delayed callbacks, ending a drag outside a destination, and native focus transfer that preserves selection. UI scenarios cover dragging an unselected task, dropping it in its current folder, and releasing it over the editor.

The app and test sources compiled with `build-for-testing`. Reading Reduce Motion through AppKit was verified. Tests and on-screen checks were not run. Manual checks were pending for animation and highlight timing in both appearances, full screen, search, Escape, and rapid folder switching.

The universal DMG was prepared for local testing. The packaging script checks both architectures, localization, the icon, entitlements, the local ad-hoc signature, and the mounted DMG contents.
